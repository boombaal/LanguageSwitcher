## [2026-10-04] «еще», «где» попадают в отложенную очередь как неоднозначные   [open]

**Что происходит:** под RU обычные слова «еще» / «где» ставятся в очередь (`ambi2`), как будто это могут быть
английские «tot» / «ult».
**Причина:** `WordPlausibility.score01` насыщается до 1 не только на точном слове, но и на префиксе
(«tot» ← total, «ult» ← ultimate), а в `ru.txt` лежали почти все двухбуквенные сочетания («ещ», «шт»…).
Точное слово и «похоже на слово» были неразличимы.
**Правка (не закоммичено, собрано и установлено, на живом вводе не проверено):**
- `LanguageScorer.score` — точное слово в текущей раскладке против лишь «правдоподобного» чтения в другой → `ok_*`;
  зеркально, от 4 букв точное слово в другой раскладке → `to_*` («еруку» → «there»). Для 3 букв по-прежнему ждём.
- `LexiconStore.sanitized` — из списков бандла убираются не-слова и 1–2-буквенный мусор (белый список).
- В `ru.txt` дописаны 175 частых форм, которых не было («меня», «были», «хочу», «знаю»…).
- В launch.log теперь пишется решение по каждому спорному слову: `EventTap: word «a»/«b» → code (queue=N run=K)`.
- `LaunchLog` дописывает в конец файла вместо чтения и перезаписи всего лога на каждую строку; ротация на 2 МБ.
- Тесты: `swift test` (59 тестов, `Tests/LanguageSwitcherCoreTests`).

## [2026-10-04] Фраза из коротких слов не переключает раскладку   [open]

**Что происходит:** под RU набрано «щк тще ещ иу» (= «or not to be») — раскладка не меняется, текст остаётся.
**Как воспроизвести:** RU-раскладка, после русского слова набрать `or not to be`. Обратный случай: под EN `yj z yt` (= «но я не»).
**Ожидается:** фраза переписывается в другую раскладку.
**Причина:** слова в 2 буквы — `short` (minWordLength=3), «not» после RU-слова — `hold_ru_ctx`; уверенного
слова, которое разрешило бы очередь, нет, через 8 с очередь протухает.
**Правка (коммит cf43908; проверено по логу 2026-10-04: «щк тще ещ» → «or not to», «yj z yt» → «но я не»):**
`ForeignRunDetector` (`DeferredRewritePlanning.swift`), в обе стороны. Срабатывает на 3-м слове подряд,
если у каждого чтение в другой раскладке — точное слово словаря, минимум у двух на экране не слово текущего
языка, и хотя бы одно слово из 2+ букв. В логе: `EventTap: short-run N слов → en|ru`.
Замечено попутно: в `Lexicon/ru.txt` есть мусор («ещ», «ше», «цу», «шт») и нет «меня».

## [2026-09-07] Слово пропадает, на его месте двойной пробел   [open]

**Что происходит:** печатаю по-русски «какие еще вопросы» — слово из фразы
пропадает, а на его месте остаётся двойной пробел.

**Как воспроизвести:**
- Раскладка: RU.
- Ввод: `какие еще вопросы` (со скоростью обычного набора, пробелы между словами).
- Приложение: (уточнить — где именно поймано).

**Ожидается:** текст остаётся `какие еще вопросы`, ничего не удаляется,
раскладка не переключается.

**Доказательство (launch.log, `~/Library/Application Support/LanguageSwitcher/`):**

```
2026-09-08T02:35:46Z EventTap: deferred 1 сегм. (ambi+межслов.) → ru + «вопросы» backspaces=11 insertPlan=«tot вопросы»
2026-09-08T02:35:46Z EventTap: deferred (RU resolve) type «tot вопросы» ruID=com.apple.keylayout.RussianWin
2026-09-08T02:35:46Z EventTap: deferred HID end backspaceN=11 typedLen=11 afterSid=com.apple.keylayout.RussianWin
```

Та же форма многократно 07–08 сен: «еще поле»→`«tot поле»`, «еще там»→`«tot там»`,
«еще нам»→`«tot нам»`, «еще пропадает»→`«tot пропадает»`, «где все»→`«ult все»`,
«где и как»→`«ult b как»`. Каждому событию непосредственно предшествует
`KeyboardRegistry: 1 sources (TIS list query 0)`.

**Причина:** «еще» набрано клавишами `t o t`; слово кладётся в отложенную очередь
как ambiguous (латинское чтение «tot» ~ англ. слово + короткое). Когда следующее
слово резолвится в `ru`, конвейер перепечатывает очередь и подставляет **латинское
чтение клавиш** (`p.alternateScript` = «tot») вместо кириллицы на экране
(`p.displayed` = «еще»). В `EventTapController.targetForPending()` (~строки 480–500)
ветки, берущие кириллическое чтение из RU-раскладки, не срабатывают, т.к. реестр
раскладок пуст (`TIS list query 0` — одна включённая раскладка / enumerate TIS
вернул 0): `reg.enabledSources` и `langTag(forSourceID:)` пустые → `curLang == ""`
→ срабатывает фолбэк `curLang != want → return p.alternateScript` (латиница).
Двойной пробел — вторично: «какие tot вопросы» → «tot» затем стирается отдельным
проходом как англ. мусор, остаётся «какие ␣␣ вопросы».

**Первопричина пустого реестра (найдено 2026-10-04):** в
`EnabledKeyboardSourcesRegistry.swift:182-183` ключи фильтра TIS написаны неверно:
`"TISInputSourceIsSelect"` / `"TISInputSourceASCIICapable"` вместо
`kTISPropertyInputSourceIsSelectCapable` (`"TISPropertyInputSourceIsSelectCapable"`) /
`kTISPropertyInputSourceIsASCIICapable`. `TISCreateInputSourceList` с неизвестным ключом
всегда отдаёт `[]` (проверено скриптом: неверный ключ → `[]`, верный → `[Canadian, RussianWin]`).
Реестр живёт на фолбэке `TISCreateASCIICapableInputSourceList` = одна Canadian, RussianWin в нём
нет никогда. В логе все 4663 refresh'а — `1 sources (TIS list query 0)`, ни одного с 2.
Следствия: `readingsByID` без RU-чтения; `srcs.count >= 2` всегда false → `scoreMulti` и
`tryResolveTwoWordPhrase` — мёртвый код; 148 из 156 отложенных `→ ru` вставок содержат латиницу
(«tot» ×77, «ult» ×42, «z», «b», «d»…). Обратное направление (`→ en`) чистое: 0 из 223.

**Правка (2026-10-04, не закоммичено, собрано, на живом вводе не проверено):**
1. `EventTapController.targetForPending` — если чтения из реестра нет, выбираем
   `displayed`/`alternateScript` по алфавиту целевого языка (`isInScript`), а не по `curLang`.
2. `EnabledKeyboardSourcesRegistry.swift:182-183` — ключи заменены на системные константы
   `kTISPropertyInputSourceIsSelectCapable` / `kTISPropertyInputSourceIsASCIICapable`.
   Побочный эффект: впервые включаются `scoreMulti` и `tryResolveTwoWordPhrase` — следить за логом.

Проверка: после запуска новой сборки в launch.log должно быть `KeyboardRegistry: 2 sources (TIS list query 2)`,
а в `→ ru … insertPlan` не должно быть латиницы. Статус оставлен open до подтверждения.
